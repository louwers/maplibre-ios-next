# maplibre-ios-next

MapLibre iOS with the public API of
[MapLibre iOS](https://github.com/maplibre/maplibre-native/tree/main/platform/ios)
7.0.0, implemented on the C API of
[MapLibre Native FFI](https://github.com/maplibre/maplibre-native-ffi) instead
of on the C++ core. It depends on the FFI's published Swift package,
[maplibre-native-ffi-distribution](https://swiftpackageindex.com/maplibre/maplibre-native-ffi-distribution)
0.202610.3, and links nothing else of MapLibre Native.

```swift
.package(url: "https://github.com/louwers/maplibre-ios-next", branch: "main")
// ...
.product(name: "MapLibre", package: "maplibre-ios-next")
```

The module is `MapLibre`, so it replaces classic MapLibre iOS without source
changes (the two cannot be in one app). iOS 15.5 and later, arm64 devices and
arm64 simulators.

## How it relates to MapLibre iOS

- **The public API is classic's.** The 85 public headers are byte-identical to
  those of the 7.0.0 `MapLibre.xcframework` (the style layer headers are
  generated by the upstream generator), and the parity harness checks the
  Objective-C symbol graph, the Swift interface and that every class, method
  and constant exists at runtime.
- **The implementation is classic's where it can be.** The files of
  `platform/darwin` and `platform/ios` at `ios-v7.0.0` are copied; those that
  changed start with `// Based on platform/… at ios-v7.0.0`, and
  `scripts/diff-upstream.sh` shows the changes. What talked to the C++ core
  talks to the C API now, through a few new files:
  - `Sources/MapLibre/ffi/` bridges the C API's asynchronous runtime to the
    synchronous model of MapLibre iOS (`MLNFFI.h` explains how).
  - `Sources/MapLibre/ios/MLNCoreShim.h` gives `MLNMapView.mm` the subset of
    the core's `Map` interface it used, on the C API, including an emulation
    of the core's annotation manager.
  - Style layer classes are generated from the style specification
    (`scripts/style-code/`), reading and writing properties as style-spec
    JSON.
- **Where the C API falls short**, [C_API_GAPS.md](C_API_GAPS.md) says what
  classic did, what the C API lacks and what this package does instead.

## Comparing with classic MapLibre iOS

[Parity/](Parity/) builds the same tests against this package and against
classic MapLibre iOS 7.0.0 from
[maplibre-gl-native-distribution](https://github.com/maplibre/maplibre-gl-native-distribution)
and reports every difference:

```sh
Parity/run.sh            # API surface, behaviour and rendering, both implementations
open Parity/out/report.html
```

It compares the public API (headers, symbol graphs, Swift interface, runtime
coverage), MapLibre iOS's own unit tests, traces of camera, delegate, style,
query, annotation and offline behaviour, every getter and setter of every
style property, and render tests through `MLNMapSnapshotter` and on-screen
map views. See [Parity/README.md](Parity/README.md).

## Development

```sh
scripts/fetch-upstream.sh                  # upstream sources and the classic XCFramework into .upstream/
xcodebuild -scheme MapLibreNext -destination 'generic/platform=iOS Simulator' build
scripts/check-file.sh Sources/MapLibre/darwin/MLNStyle.mm   # type-check one file
(cd scripts/style-code && npm ci && node generate.mjs)      # regenerate style code
```
