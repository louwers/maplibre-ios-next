# Parity harness

Compares maplibre-ios-next with classic MapLibre iOS: the same public API,
the same tests, the same render-test styles, run against both
implementations, with one report of every difference.

- **classic**: MapLibre iOS 7.0.0 as published in
  [maplibre-gl-native-distribution](https://github.com/maplibre/maplibre-gl-native-distribution)
  (`MapLibre.dynamic.xcframework`, a Release build).
- **next**: this repository's package, on MapLibre Native FFI.

Both export the module `MapLibre`, so they cannot share a build. The harness
generates one Xcode project per implementation from the same template and
compiles the same test sources into each.

## Running

```sh
Parity/run.sh                       # everything, both implementations
Parity/run.sh api                   # public API only (no build, a few seconds)
Parity/run.sh behaviour --impl classic
Parity/run.sh render --impl both
Parity/run.sh behaviour --stability # run classic twice to flag timing-dependent values
PARITY_RENDER_LIST=all Parity/run.sh render   # all 1350 upstream render tests
```

Then open `Parity/out/report.html` (self-contained) or read
`Parity/out/report.md`. Raw outputs are in `Parity/out/<impl>/`.

Requirements: Xcode with an iOS Simulator runtime, XcodeGen
(`brew install xcodegen`), Node.js only to regenerate the property suite.
`run.sh` creates a simulator named "MapLibre Parity" (an iPhone 17 on the
newest installed iOS) so that other simulator users do not interfere, and
fetches the upstream sources and the classic XCFramework into `.upstream/`
(`scripts/fetch-upstream.sh`).

If maplibre-ios-next does not build, its parts are reported as not run, with
the first compiler errors in `out/next/build-errors.txt`; classic still runs.

## What is compared

### 1. API surface (`api/`)

`api/check-api.sh` compares classic's framework headers with
`Sources/MapLibre/include/MapLibre`:

- the header files, byte for byte;
- the Objective-C symbol graphs from `clang -extract-api`, symbol by symbol
  (kind, declaration, availability, documentation, relationships);
- the Swift view of each module from `swift-api-digester -dump-sdk`, with
  `-diagnose-sdk` for breaking changes. The digester only reports declarations
  of the top-level module, so it runs on a copy of the headers with a module
  map without per-header submodules.

It also generates `Tests/Coverage/MLNAPICoverageTests.m` from the AST of
classic's headers: 1138 runtime checks that every class and protocol exists,
every method and property accessor (including the required members of the
product's protocols that classes adopt) responds, and every exported constant
and function resolves with `dlsym`. Six symbols are missing from classic itself
at runtime (`api/coverage-known-classic-gaps.json`, with reasons); the test
reports them but does not fail on them.

### 2. Behaviour (`Tests/`)

One test bundle, hosted by a minimal app (`HostApp/`), with:

- **`Tests/Upstream/`**: MapLibre iOS's own tests, copied by
  `Tests/Upstream/import-upstream.py` from the upstream release. Tests that use
  the C++ core or private headers are removed; small private helpers become
  shims in `Tests/Support/ParityShims.h`. `Tests/Upstream/ADAPTATIONS.md` lists
  every change. Re-run the script after updating `scripts/upstream.env`.
- **`Tests/Trace/`**: tests that record what the API returns instead of
  asserting it, through `ParityRecorder` (JSON lines in
  `out/<impl>/traces/<suite>.jsonl`): camera and projection, delegate callback
  order, the style object model, queries, feature state and clusters,
  annotations, GeoJSON, expressions and predicates, and an offline pack against
  local tiles. The fixtures are in `Fixtures/`.
- **`Tests/Trace/Generated/MLNStylePropertyParityTests.m`**: every property of
  every layer type and of the light, on a layer in the style and on a pending
  layer: the default, a constant, a zoom expression, a data expression where
  allowed, an attribute expression, a reset, and the transition. Generated by
  `node scripts/style-code/generate.mjs` from
  `scripts/style-code/templates/MLNStylePropertyParityTests.m.ejs`.

`compare.py` matches trace values by suite, test, key and occurrence, with a
relative tolerance of 1e-5 on numbers (also inside descriptions); object
addresses, app container UUIDs and bundle IDs are ignored. With
`--stability`, values that differ between two classic runs are counted as
unstable rather than as differences.

### 3. Render (`render/`, `Tests/Render/`)

`MLNRenderParityTests` renders upstream render-test styles
(`metrics/integration/render-tests` of the upstream release) through
`MLNMapSnapshotter`, and a subset (`render/onscreen.txt`) through an on-screen
`MLNMapView` captured after `mapViewDidFinishRenderingMap:fullyRendered:`. It
reads the styles and their data from `.upstream/` on the Mac, rewriting
`local://` URLs to `file://`. Tests that need operations, debug modes or other
features outside the public API are skipped with a reason.
`render/curated.txt` (the default) has two tests per property directory that
need no glyphs or sprites.

`compare.py` compares the images of both implementations with each other, not
with upstream's expected images, using pixelmatch's colour metric and a
threshold of 0.1, and writes difference images to `out/render-diff/`.

On GitHub's macOS runners, a few hillshade tests differ by up to 0.1 % of
pixels, a different few in each run; on a Mac they are identical. Treat
differences of that size in hillshade on CI as noise of the runner's GPU.

## Reading the report

- **Status**: whether each part built and ran.
- **API surface**: should be zero differences.
- **Runtime API coverage**: symbols that next does not implement.
- **MapLibre iOS's own tests**: pass/fail per implementation and every test
  whose outcome differs. Some tests fail against classic too, because the
  distributed framework is a Release build: `MLNMapViewLayoutTests`'
  `…InvalidPosition` tests expect `NSAssert` to throw, and two
  `MLNExpressionTests` crash classic. Compare outcomes, not absolute results.
- **Traces**: per suite, how many recorded values are the same, different, or
  recorded by one implementation only (a test that crashed or stopped early).
- **Render**: per test, whether each implementation rendered it and the share
  of differing pixels; the HTML report shows both images and the difference.

## Layout

```
run.sh               entry point
make-projects.sh     generates build/<impl>/Parity.xcodeproj (XcodeGen)
project.yml.in       the project template
compare.py           builds the report
api/                 API surface scripts and the coverage generator
HostApp/             the test host app
Tests/Support/       ParityRecorder, ParityMapTestCase, shims
Tests/Coverage/      generated API coverage test
Tests/Upstream/      copied upstream tests and their importer
Tests/Trace/         trace tests (Generated/: the property suite)
Tests/Render/        the render runner
Fixtures/            local styles for the trace tests
render/              render-test lists
```
